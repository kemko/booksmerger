# Bookmerger: сборник из FB2 и EPUB с сохранением структуры и изображений

## Overview

Утилита на Python принимает название сборника и упорядоченный список ссылок, скачивает книги, преобразует FB2 через fb2cng и создаёт единый EPUB 3.3.
Сохраняются вложенность оглавлений, сноски и обратные ссылки, аннотации, иллюстрации и оформление исходных документов. Перед каждым произведением
размещаются оригинальная обложка при наличии и библиографические сведения. Метаданные участников объединяются с сохранением ролей.
По предыдущему согласованию иллюстрации и обложки остаются в исходных форматах, SVG сохраняется векторным. Максимальное сжатие применяется к
ZIP-контейнеру EPUB. Поддержка обфусцированных шрифтов исключена.
Выбран EPUB: он позволяет сохранять документы и ресурсы исходных EPUB, а fb2cng поддерживает преобразование FB2 в EPUB3. [Руководство
fb2cng](https://github.com/rupor-github/fb2cng/blob/master/docs/guide.md).

## Context

- Репозиторий пустой: исходного кода, тестов и проектных соглашений нет.
- Новые файлы: pyproject.toml, src/bookmerger/, tests/, README.md, .github/workflows/tests.yml.
- Интерфейс: bookmerger --title "Название" --output collection.epub URL1 URL2 …
- Дополнительно: --input-file для списка ссылок по строкам; список и позиционные ссылки взаимоисключающие.
- Повторяющиеся ссылки означают повторное включение произведения. Порядок сохраняется без сортировки и удаления дублей.
- Вход: прямые HTTP(S)-ссылки на FB2, EPUB2/3 и ZIP с единственным FB2. Страницы каталогов и авторизация не входят в первую версию.
- По уточнениям пользователя обработка DRM и обфусцированных шрифтов не требуется. Обычные встроенные шрифты сохраняются.
- Основные зависимости: httpx, lxml, tinycss2. CLI, ZIP, временные файлы и запуск процессов — стандартная библиотека.
- Пригодность EbookLib проверяется на контрольных книгах: библиотека используется только при сохранении необходимых документов, ресурсов и метаданных. Если проверка выявит потери, используется zipfile и lxml для адресных изменений. В проекте остаётся один механизм обработки.
- Проверки: pytest, pytest-cov, Ruff, EPUBCheck.
- Версии зависимостей и внешних инструментов фиксируются после проверки совместимости, лицензий, сопровождения, известных уязвимостей и транзитивных зависимостей.

## Development Approach

- Testing approach: Regular — реализация, затем регрессионные тесты.
- Каждая задача завершается полностью перед следующей.
- Каждая задача включает новые или обновлённые тесты; все тесты должны проходить перед следующей задачей.
- Исходные XHTML сохраняются отдельными документами: это предотвращает коллизии идентификаторов и взаимное влияние стилей.
- Растровые ресурсы копируются побайтно. SVG остаётся векторным; изменения допустимы только для сохранения адресов связанных ресурсов.
- Без плагинной архитектуры, сервера и базы данных.
- Ошибка любой книги прерывает сборку с указанием источника и причины. Неполный сборник не выдаётся за успешный результат.
- Запись результата атомарная. Существующий файл заменяется только с --overwrite.
- Конструкция, которую невозможно сохранить корректно, вызывает понятную ошибку до публикации итогового файла.
